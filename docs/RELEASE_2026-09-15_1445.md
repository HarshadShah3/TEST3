# Iteration 2 release — 0915 1445 AEST

## Why this push was made

Team feedback reported that some sessions still appeared to read local data and
that some deployed pages showed errors, while the current local website was
working normally. The most likely cause is that different people were opening
different branches or deployments. This release makes the active version and
runtime data source visible and independently verifiable.

## What changed

- Added a prominent `BUILD 0915 1445` banner to every page.
- Added a live `/api/data-sources` check to the banner.
- The banner only reports success when the API confirms
  `aiven-mysql`, `aiven-mysql-direct`, and `localRuntimeFallback: false`.
- Added explicit `dataMode: aiven-mysql-only` and
  `localRuntimeFallback: false` metadata to the runtime data contract.
- Added the build label, branch, expected provider and no-fallback flag to
  `/api/health` in both the Express and serverless API entry points.
- Increased the browser API timeout from 3 to 15 seconds so an Aiven/serverless
  cold start is not incorrectly displayed as a database error.
- The build banner automatically retries after a temporary backend outage and
  periodically re-verifies a healthy Aiven connection.
- Excluded the obsolete local-data embedding helper from Git so it cannot be
  included in a future deployment by mistake.

## Runtime data rule

Normal website execution reads regional profiles, recommendations, comparison
data, shortlist data, 2036 projections and map geometry from Aiven MySQL. Local
CSV/JSON/GeoJSON files remain only as deterministic test/import fixtures; they
are not a runtime fallback. If Aiven is unavailable or misconfigured, the site
must show an error instead of silently substituting local business data.
